# Mu2eBO Gaussian-process surrogate MCP server

The `surrogate` MCP server of [Mu2e/Mu2eBO](https://github.com/Mu2e/Mu2eBO) (`surrogate/mcp_server.py`, release
v00_02_00). It is a thin adapter: the tools are generated by the `surrokit` engine
([oksuzian/surrokit](https://github.com/oksuzian/surrokit), MIT) from Mu2eBO's studies and leaderboards. This card is
a draft written from the repository for review by its authors.

## What it does

| Tool | Purpose |
|---|---|
| `list_problems` | One problem per registered study |
| `stats` | Knobs (names, units, bounds), objectives (name, direction, transform, label), the best design and the observed range of the primary objective |
| `predict` | Posterior mean and uncertainty of every objective at given configurations |
| `suggest` | The next batch of points, with the same pickers and seeding as a production campaign round (`qnehvi`, `qlnei`, `budget_sob`, `hybrid`; default `hybrid`) |
| `refit` | Refit after new leaderboard rows (fits are cached and refreshed automatically when the board grows) |

Every objective axis is presented as maximized (for example radiation damage as `-log10(flash_edep)`), and
in-flight evaluations are passed as pending points, so a suggestion does not duplicate running work.

## Role in the Mu2e Genesis project

The surrogate in step 5 of the Run-1 optimization workflow (`mu2e-run1-optimization`). The phase 1 proposal uses
Bayesian optimization for local, sample-efficient search, with the agent orchestrating exploration across
qualitatively different configurations; a global surrogate over the whole configuration space is left to phase 2.

## Access and limitations

- Runs as a stdio MCP server from a Mu2eBO checkout on Fermilab Mu2e machines; it reads the leaderboards in that
  checkout. No jobs, no writes.
- A surrogate is only as good as its leaderboard: predictions far from evaluated points are uncertain, and the
  uncertainty is reported for that reason.
- The repository declares no license; ask the authors before reuse.
